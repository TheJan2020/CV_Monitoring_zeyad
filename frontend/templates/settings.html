MQTT — publish baby_in_crib to Home Assistant

When enabled, the hub maintains a persistent MQTT connection to your broker (usually Mosquitto on the same LAN) and publishes the aggregate baby_in_crib state as ON or OFF every time it changes. If Home Assistant Discovery is on, the entity binary_sensor.baby_in_crib appears in HA automatically with no extra YAML.

How to wire this up on Home Assistant

  1. Install Mosquitto broker from HA → Settings → Add-ons → Add-on Store. Start it.
  2. HA → Settings → People → Add an MQTT-only user (e.g. primeanalyze) with a strong password.
  3. HA → Settings → Devices & Services → Add Integration → MQTT. Point it at the Mosquitto add-on. Confirm it shows "Connected".
  4. Back here: tick "Enabled", fill broker IP (your HA host's LAN IP), port 1883 (TCP default), the MQTT username + password from step 2, leave the rest as defaults. Click "Test connection" — should say "connected".
  5. Click "Save". Within ~5 seconds, in HA → Settings → Devices & Services → MQTT → Devices, a new device "PrimeAnalyze Baby Monitor" will appear with one entity: binary_sensor.baby_in_crib. That's the one to use in automations.

If you're using MQTT over WebSocket: switch Transport to "WebSocket", set port 8083 (or whatever you configured in your broker config), leave the WS path as /mqtt unless you've customised it. TLS is independent of transport.
